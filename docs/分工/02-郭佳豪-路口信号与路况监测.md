## 2. 第 2 周：核心算法（services/algorithms.py，纯函数先行）

> 铁律：算法不碰数据库、不读全局状态、可单测；前后端各写一份、结果必须一致。

### 2.1 `webster_calc(phases)`

- 入参：`[{"name": "东西直行", "flow": 1200, "lanes": 3}, ...]`
- 公式：`y_i = q_i / (1800 × n_i)`；`Y = Σy_i`；`L = 6 × 相位数`；`C0 = (1.5L + 5) / (1 − Y)`，钳制 [40, 180]
- 分配：绿灯按 `y_i / Y` 分配可用绿灯（`cycle − L`），最小 15s；不足则从其他相位按比例扣减；四舍五入后再从最大相位逐步扣减，保证总和不超周期
- 过饱和：`Y ≥ 0.95` → 周期直接取 180
- 不可行输入：相位数 > 12 或 `L + 15 × 相位数 > 180` → 抛 ValueError（路由转 20006）
- 校验：flow ≤ 0 或 lanes ≤ 0 → ValueError
- 返回：`{cycle_seconds, total_lost, y_sum, oversaturated, phases: [{name, green, y}]}`
- 验收：默认四相位 1200/400/1000/350、3 车道 → 周期落在 [40,180]，各绿灯 ≥15，Σ绿灯+g L = 周期；flow=3000 单相位 → oversaturated=true、cycle=180

### 2.2 `congestion_level(saturation)`

- 分段：`<0.4 → 0`；`<0.7 → 1`；`<0.9 → 2`；`≥0.9 → 3`；返回 int
- 验收：0.39→0、0.4→1、0.69→1、0.7→2、0.9→3

### 2.3 `speed_by_saturation(base_speed, saturation)`

- `factor = max(0.12, 1 − 0.78 × saturation^1.8)`；返回 `round(max(8.0, base_speed × factor), 1)`
- 用途：流量上报未传 speed 时自动推算，保证大屏"平均车速"合理

### 2.4 `hour_flow_rate(hour, section_factor=1.0, weekday=1, rand_value=None)`

- 高峰用高斯峰值：早高峰中心 8.25（σ=0.8）、晚高峰中心 18.25（σ=0.8）
- 周五（weekday==4）晚高峰 ×1.15；周末（weekday≥5）整体 ×0.6；rand_value 由调用方传入以保证可测试
- 验收：08:00 流率显著高于 03:00；周五 18:00 > 周一 18:00；周末 08:00 < 工作日 08:00

### 2.5 前端同源实现 `frontend/src/utils/algorithms.ts`

- `websterCalc(phases)` 与 `estimateParkingFee(...)`（后者归李嘉诚复用，我负责 Webster 部分）；
- 页面在点"计算"时**先本地算一遍**即时展示，再调后端接口核对，二者不一致视为缺陷。

## 4. 第 3 周：定时任务（tasks/scheduler.py）

启动入口 `start_scheduler()`（`main.py` 的 startup 钩子在 `TESTING=0` 时调用），停止 `stop_scheduler()`。

| 任务 | 函数 | 触发器 | 逻辑 |
|---|---|---|---|
| 模拟流量 | `_mock_traffic_flow()` | interval 60s | 遍历启用路段 → `hour_flow_rate(hour, section_factor, weekday, random())` 算流率 → `_insert_flow` 落库（含 saturation/level）|
| 信号推进 | `_advance_signal_status()` | interval 10s | 每路口按当前方案相位顺序推进 `remaining_seconds`，归零切下一相位；无方案用默认四相位 |
| 数据清理 | `cleanup_flow_data(db=None)` | cron 03:30 | 删除 `recorded_at < now − FLOW_RETENTION_DAYS(90)` 的流量行；`FLOW_RETENTION_DAYS=0` 时禁用；只清遥测数据不碰业务单据 |

**数据清理的可测性设计**：`cleanup_flow_data` 支持传入 db 会话（不传则自建），这样 `test_export_upload.py::TestFlowRetention` 可以直接构造过期数据验证：
- `test_cleanup_deletes_only_expired`：过期行被删、保留期内行不动；
- `test_cleanup_disabled_when_zero`：`FLOW_RETENTION_DAYS=0` 时一行不删。

**开关**：`.env` 的 `MOCK_DATA_ENABLED` 控制是否注册两个 interval 任务（演示时若不想数据乱动可关闭；清理任务独立不受影响）。

## 7. 第 5 周：与左栋升（大屏）的联调重点

大屏 `/dashboard/realtime` 需要我的数据，我保证字段口径：

| 大屏组件 | 我用什么数据 | 我保证 |
|---|---|---|
| 24h 流量趋势 | traffic_flow 按小时桶 avg(flow) | 最近 24 小时每个整点有数据（乱序时间戳按 bucket 聚合） |
| 路口地图散点 | road_section 最新 flow + intersection 经纬度 | 每个路口至少关联一条路段，坐标落在模拟路网范围 |
