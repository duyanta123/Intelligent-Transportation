## 1. 第 1 周：需求与设计

### 1.1 计费规则口径（答辩必背）

| 规则 | 说明 |
|---|---|
| 免费时长 | 入场时长 ≤ free_minutes 分钟：0 元 |
| 首小时 | 超出免费时长后第一段按 first_hour_fee（不足 1 小时按 1 小时算） |
| 每小时 | 第二小时起按 hourly_fee（不足 1 小时按 1 小时算，向上取整） |
| 单日封顶 | 每满 24 小时为一段，按 daily_cap 封顶；剩余尾段单独计算且同样受封顶约束 |

默认规则（种子）：免费 15 分钟、首小时 5 元、每小时 3 元、单日封顶 40 元。

计费查表（用 `calc_parking_fee(minutes, 15, 5, 3, 40)` 手算即可复现，验收时现场演示）：

| 时长 | 计算过程 | 金额 |
|---|---|---|
| 0 / 10 / 15 分钟 | 免费期内 | 0 元 |
| 16 分钟 | 超出 1 分钟 → 首小时段 | 5 元 |
| 60 分钟 | 首小时整 | 5 元 |
| 61 分钟 | 首小时 5 + 第 2 小时 3 | 8 元 |
| 75 分钟 | 首小时 5 + 1 小时（ceil((75−15)/60)=1） | 5 元 |
| 76 分钟 | ceil((76−15)/60)=2 → 5 + 3 | 8 元 |
| 24 小时 | 完整一天段封顶 | 40 元 |
| 24 小时 + 1 分钟 | 40 +（首小时 5 与封顶 40 取小） | 45 元 |
| 3 天 + 1 分钟 | 3 × 40 + 5 | 125 元 |

> 规则以 `calc_parking_fee` 为唯一事实来源（纯函数 + 单测 `test_multi_day` 锁定）；前端预估必须与后端同值。

## 2. 第 2 周：计费算法（services/algorithms.py，纯函数）

### 2.1 `calc_parking_fee(minutes, free_minutes, first_hour_fee, hourly_fee, daily_cap) -> float`

实现步骤（逐步可讲）：

1. `total = float(minutes)`；`total <= 0` 直接返回 `0.0`；
2. `full_days = int(total // 1440)`；`remainder = total − full_days × 1440`；
3. `fee = full_days × daily_cap`（每个完整 24 小时段按封顶计）；
4. 尾段：`remainder > free_minutes` 时
   - `billable_hours = ceil((remainder − free_minutes) / 60)`（向上取整）；
   - 尾段费用 `= min(first_hour_fee + (billable_hours − 1) × hourly_fee, daily_cap)`；
   - 累加到 fee；
5. `return round(fee, 2)`。

### 2.2 `calc_parking_fee_dt(enter, exit_time, free_minutes, first_hour_fee, hourly_fee, daily_cap) -> float`

- 空值保护：任一为 None 返回 0.0；
- `minutes = (exit_time − enter).total_seconds() / 60.0` → 调 `calc_parking_fee`；
- 出场接口只调这个包装，保证"时间差 → 金额"只在一处实现。

### 2.3 前端同源实现 `frontend/src/utils/algorithms.ts::estimateParkingFee(...)`

- 与后端同参数同规则；出场弹窗里**结算前预估**金额（"需付 ¥x"）；
- 前端单测与后端单测使用同一组数据，任何一侧改规则必须两侧同改并补用例。

## 3. 第 2-3 周：停车接口实现（routers/parking.py）

### 3.1 `_lot_out(lot, rule=None)` 输出口径

```
{id, name, address, total_slots, used_slots, free_slots(max(0, total-used)),
 occupancy(round(used/max(1,total)*100,1)), fee_rule_id, fee_rule_name}
```
user 角色用它看"剩余车位"；左栋升大屏停车占用条形图也用同一口径。

### 3.2 入场 `parking_enter`（并发安全是重点）

1. 参数：`parking_lot_id`、`plate_no`（Form）+ `file`（可选拍照）；
2. `normalize_plate` → `is_valid_plate` 不合法 → 20002；
3. **停车场行加锁**：`db.query(ParkingLot).filter(id, is_deleted==0).with_for_update().first()`，不存在 → 20001；
4. **重复入场校验**：同停车场同车牌 status=inside 存在 → 30002；
5. **满位校验**：`used_slots >= total_slots` → 30001；
6. `save_image(file)` 存图（可空）；
7. 建 `ParkingRecord(status=inside, enter_time=now())` → `lot.used_slots += 1` → `log_op("入场", ...)` → commit；
8. 返回 `{record_id, plate_no, enter_time}`。

> 为什么加 `with_for_update()`：防满位超卖、同车牌重复入场、`used_slots` 读改写丢失更新；端点用同步 def（FastAPI 丢线程池），避免 DB/文件 IO 阻塞事件循环。

### 3.3 出场 `parking_exit`

1. 同样对停车场行加锁（与入场互斥；双击出场时第二下在"记录非 inside"处被拒）；
2. 查该车 `status=inside` 的最近一条记录，没有 → 30003；
3. 取停车场绑定 fee_rule（无规则则费用 0）；
4. `exit_time = now()`；`fee = calc_parking_fee_dt(record.enter_time, exit_time, rule.free_minutes, float(rule.first_hour_fee), float(rule.hourly_fee), float(rule.daily_cap))`；
5. 更新记录：exit_time、fee、status=finished；`lot.used_slots = max(0, used_slots − 1)`；
6. `log_op("出场", f"车辆 {plate} 驶出 {lot.name}，结算 {fee} 元")`；
7. 返回 `{record_id, plate_no, enter_time, exit_time, fee}`。

### 3.4 查询 `list_records`

- 支持 `plate_no`（模糊、先 normalize）、`parking_lot_id`、`status`、`enter_start`、`enter_end`；
- **时间上界 +1 秒缓冲**：MySQL DATETIME 对小数秒四舍五入，`end=now()` 会漏掉刚写入的行；
- 返回列表附 `parking_lot_name`、`image_url`（入场拍照回显）；
- 验收用例：`test_enter_time_range_filter`。

## 4. 第 3 周：车牌识别（services/lpr_service.py、routers/lpr.py）

### 4.1 `lpr_service.py` 要点

| 函数 | 职责 |
|---|---|
| `_init_catcher()` | try/except 延迟导入 hyperlpr3，未安装时应用仍可启动 |
| `preload_async()` | 启动后台线程**预热模型**（约 12MB，首次自动下载），不阻塞启动、不在首个请求内同步加载 |
| `_run_recognize(image_bytes)` | 解码图片 → 推理 → 返回识别结果列表 |
| `recognize_plate(image_bytes) -> dict` | 取置信度最高结果，返回 `{plate_no, confidence}`（置信度保留 4 位） |

### 4.2 `routers/lpr.py::recognize`（同步端点）

1. 后缀白名单（`UPLOAD_SUFFIXES`）不通过 → 90002；
2. 读文件：空或 > 5MB → 90002；
3. `is_image_bytes(content)` 按 **magic bytes** 二次校验（扩展名可伪造）→ 90002；
4. 调 `recognize_plate`；任何异常 → 日志 warning + 90003（"车牌识别失败，请手动录入车牌"，503）；
5. 成功：`log_op("识别", f"车牌识别：{plate_no}（置信度 {confidence}）")`，返回 `{plate_no, confidence}`。

### 4.3 `utils/upload.py::save_image(file)`

- 后缀白名单 jpg/jpeg/png/webp；≤5MB；magic bytes 校验；
- 文件名 = `%Y%m%d%H%M%S` + 微秒 6 位 + 原后缀（非 uuid）；存 `backend/uploads/`；返回 `/static/uploads/{name}`，测试断言 URL 前缀与落盘存在
- 前端回显由 `main.py` 挂载的 `/static/uploads` 静态目录提供。

### 4.4 降级路径（答辩演示预案）

识别失败（如首次无网络下载模型超时）→ 前端提示"手动录入车牌"，车牌输入框仍可正常走入场流程（demo.md 第 4 节已注明）。

## 8. 常见坑位与修复记录

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 并发入场导致车位超卖 | 无行锁，读改写竞态 | `with_for_update()` 锁停车场行 |
| 2 | 同车牌重复入场 | 未查 inside 记录 | 30002 校验 |
| 3 | 出场双击产生两次结算 | 无幂等保护 | 行锁 + 记录状态二次检查 |
| 4 | HyperLPR3 阻塞事件循环 | async 端点里跑 CPU 推理 | 端点改同步 def（线程池）+ 启动后台预热模型 |
| 5 | 伪造扩展名上传可执行内容 | 只看后缀 | magic bytes 二次校验 |
| 6 | 时间上界漏查刚写入记录 | DATETIME 秒级四舍五入 | `enter_end + timedelta(seconds=1)` |
