## 1. 第 1 周：需求与设计

### 1.1 公众服务业务规则

- **公告**：admin 可新增/编辑/删除/下架；officer/user 只读**已发布**列表；`status=1 已发布 / 0 已下架`；发布时间 `published_at` 落库；
- **反馈状态机**：`pending（待受理）→ processing（处理中）→ resolved（已办结）`；已办结不可再处理 → 40001；普通用户只能看本人提交的工单；
- **处理留痕**：`handler_id`、`handled_at`、`reply`（处理答复文本）必写。

### 1.2 大屏数据契约（与郭佳豪/程靖超/李嘉诚对齐后冻结）

`GET /dashboard/realtime` 返回 `data` 结构（字段名冻结）：

```
{
  "flow_trend":   [{"time": "08:00", "flow": 1280.0}, ...],     // 最近 24 小时按小时桶 avg(flow)
  "map_points":   [{"id","name","lng","lat","level","level_name","flow","speed"}, ...],
  "roads":        [{"name","coords":[[lng,lat],[lng,lat]],"level","flow","speed"}, ...],
  "signal_dist":  [{"name": "东西直行", "value": 4}, ...],       // 按 current_phase 分组
  "violation_top":[{"name": "闯红灯", "value": 210}, ...],       // 近 7 天 TOP5
  "parking":      [{"name": "中心停车场", "total": 100, "used": 62, "rate": 62.0}, ...],
  "kpi":          {"today_flow": 12345.0, "avg_speed": 42.3, "violation_today": 18, "feedback_pending": 3},
  "updated_at":   "2026-09-23 10:20:31"
```

## 2. 第 2 周：公众服务接口（routers/service.py）

### 2.1 公告部分

1. `list_notices`：`_role_of(db, user)` 判角色；非 admin 强制 `status == 1`；`_notice_out(n)` 统一输出 `{id,title,content,publisher_name,published_at,status}`；
2. `create_notice`：标题必填、内容可空；`publisher_id = 当前用户`；`published_at = now()`；`log_op("发布公告")`；
3. `update_notice`：可改标题/内容/状态（下架=status 0）；不存在 → 20001；
4. `delete_notice`：软删 + `log_op`。

### 2.2 反馈部分

1. `submit_feedback`：`{title, content}` → `Feedback(user_id=当前用户, status=pending)`；`log_op("提交反馈")`；
2. `list_feedback`：user 分支 `user_id == current_user.id`；`_feedback_out(f)` 附提交人姓名与处理人姓名；
3. `handle_feedback`：校验状态——`resolved` 再处理 → 40001；写完 `status`、`reply`、`handler_id=当前用户`、`handled_at=now()`；`log_op("处理反馈")`。

## 3. 第 2-3 周：大屏聚合接口（routers/dashboard.py）

### 3.1 内部函数

| 函数 | 职责 |
|---|---|
| `_level_name(level)` | `LEVEL_NAMES[min(3, max(0, int(level)))]` 防脏数据越界（曾修 IndexError） |
| `_today_flow_kpi(db)` | 今日累计车流量：按小时 bucket avg(flow) 求和（小时行与分钟行不重复计数） |
| `_build_realtime(db)` | 组装 7 个板块 + `updated_at` |

### 3.2 `_build_realtime` 逐板块实现

1. **flow_trend**：`date_format(recorded_at,'%Y-%m-%d %H:00:00')` 分桶 + `avg(flow)`，取近 24h，输出 `time = bucket[11:16]`（HH:MM）；
2. **map_points**：先取每条路段最新一条流量（子查询 `max(id)` group by road_section_id），按路段两端路口聚合取最大拥堵等级，再与全部路口左连接，输出含 `level_name`；
3. **roads**：路段两端坐标都存在才输出（防大屏 null 坐标报错），附 level/flow/speed 供连线着色；
4. **signal_dist**：`SignalStatus.current_phase` 分组计数；
5. **violation_top**：近 7 天按 `violation_type` 分组 TOP5（**用 7 天窗口而非当日**，保证早晨/演示时也有数据）；
6. **parking**：每停车场 `{name,total,used,rate}`；
7. **kpi**：`today_flow`、`avg_speed`（近 1 小时均值）、`violation_today`、`feedback_pending`（pending+processing）。

### 3.3 缓存与降级（答辩亮点）

1. `dashboard_realtime` 先读 Redis `dashboard:realtime`；
2. **读失败（RedisError）→ 不抛异常，降级直查 DB**（大屏不能用缓存故障挂掉）；
3. 命中缓存 → 直接返回 JSON；
4. 未命中 → `_build_realtime` → `setex(TTL=8s)`；**写缓存失败也不影响本次响应**；
5. 前端每 10s 轮询 → 实际 DB 每 8s 最多查一次，演示"缓存削峰"。

对应测试：`TestDashboard::test_realtime_structure`（结构七键齐全）、`TestDashboard::test_realtime_redis_cache`（第二次命中缓存）。

## 4. 第 3 周：前端大屏（views/bigscreen/index.vue，500 行）

### 4.1 实现要点（按代码顺序）

| 要点 | 实现 |
|---|---|
| 自适应缩放 | `scale = min(w/1920, h/1080)`，容器 `transform: scale(...)`，监听 resize 重算 |

| KPI 数字滚动 | `kpiDisplay` 从旧值到 `kpiTargets` 做 600ms `1-(1-p)^3` 缓动 |
| 时钟 | `clock` 每秒刷新，右上角显示本地时间 |
| 地图 | ECharts `geo` + 散点按 `LEVEL_COLORS`（自由流 #2ec7c9 / 缓行 #f6e58d / 拥堵 #ff9f43 / 严重 #ee5253）着色；`roads` lines 系列流光 |

## 8. 常见坑位与修复记录

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 大屏 level_name 越界崩溃 | 脏数据 level ≥ 4 | `_level_name` 钳位 |
| 2 | Redis 挂了导致大屏整页失败 | 缓存读取未捕获异常 | `except RedisError` 降级直查 DB |
| 3 | 轮询旧响应覆盖新数据 | 请求乱序返回 | `loadSeq` 序号守卫 |
| 4 | 地图出现 null 坐标 | 路段端点路口被删 | 只有两端坐标存在才输出 roads |
| 5 | 今日 KPI 重复计数 | 小时行与分钟行相加 | 按小时 bucket avg 后求和 |
| 6 | 早晨 TOP5 为空 | 只统计当日 | 改近 7 天窗口 |
| 7 | .bat 首行中文乱码报错 | UTF-8 BOM + cmd 不识别 | 无 BOM + CRLF + `chcp 65001` |
| 8 | 演示数据日期陈旧 | 种子固定日期 | `gen_seed.py` 可重新生成刷新日期 |
| 9 | 降级提示不恢复 | 只靠轮询不重连 | "重新连接"按钮 + 成功后自动清 degraded |
